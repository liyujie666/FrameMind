## 通用 Agent Workflow 引擎设计方案

### 核心思路

将当前的**硬编码线性管道**改造为**可配置的状态图（StateGraph）引擎**，同时保持与现有 Qt 信号/槽、DI 容器、ITool 接口的兼容。

---

### 一、整体架构

```
                    ┌────────────────────────────────────────┐
                    │         WorkflowEngine (核心引擎)        │
                    │                                        │
  User Question ──▶│  WorkflowGraph (DAG 状态图定义)          │
                    │       │                                │
                    │  WorkflowExecutor (执行器)              │
                    │       │                                │
                    │  ┌────┴─────┐                          │
                    │  │ StateNode │◀── 可插拔节点             │
                    │  └────┬─────┘                          │
                    │       │                                │
                    │  ┌────┴─────┐                          │
                    │  │  Router   │◀── 条件路由              │
                    │  └────┬─────┘                          │
                    │       │                                │
                    │  WorkflowState (共享状态/上下文)         │
                    │  Checkpoint   (断点持久化)              │
                    └────────────────────────────────────────┘
```

#### 2. `IWorkflowNode` — 可插拔节点接口

```cpp
// src/service/agent/workflow/workflow_node.h

// 节点执行结果
struct NodeResult {
    QString nextRoute;          // 路由到哪个节点（空=默认边）
    bool success = true;
    QString error;
};

using NodeCallback = std::function<void(NodeResult)>;

class IWorkflowNode {
public:
    virtual ~IWorkflowNode() = default;

    virtual QString id() const = 0;
    virtual QString type() const = 0;      // "llm" / "tool" / "condition" / "parallel" / "human"

    // 异步执行，完成后回调
    virtual void execute(WorkflowState& state, NodeCallback done) = 0;

    // 可选：节点级超时（ms），0=无超时
    virtual int timeoutMs() const { return 0; }

    // 可选：最大重试次数
    virtual int maxRetries() const { return 0; }
};
```

#### 3. `WorkflowGraph` — DAG 定义

```cpp
// src/service/agent/workflow/workflow_graph.h

struct Edge {
    QString fromNode;
    QString toNode;
    QString condition;        // 空=默认边，非空=条件表达式
    int priority = 0;        // 多条边时优先级
};

class WorkflowGraph {
public:
    // 构建 API（Builder 模式）
    WorkflowGraph& addNode(std::shared_ptr<IWorkflowNode> node);
    WorkflowGraph& setEntryNode(const QString& nodeId);
    WorkflowGraph& addEdge(const QString& from, const QString& to,
                           const QString& condition = {});
    WorkflowGraph& setMaxIterations(int max);   // 防无限循环

    // 查询
    IWorkflowNode* node(const QString& id) const;
    QString entryNodeId() const;
    QList<Edge> outEdges(const QString& nodeId) const;
    int maxIterations() const { return m_maxIter; }

    // 验证（检测不可达节点、循环无终止等）
    bool validate(QString* errorOut = nullptr) const;

private:
    QMap<QString, std::shared_ptr<IWorkflowNode>> m_nodes;
    QList<Edge> m_edges;
    QString m_entryNode;
    int m_maxIter = 20;
};
```

#### 6. `ConditionNode` — 条件路由节点

```cpp
// src/service/agent/workflow/nodes/condition_node.h

class ConditionNode : public IWorkflowNode {
public:
    using Evaluator = std::function<QString(const WorkflowState&)>;

    ConditionNode(const QString& id, Evaluator eval);

    QString type() const override { return "condition"; }
    void execute(WorkflowState& state, NodeCallback done) override {
        // 同步执行条件判断，返回路由名
        QString route = m_eval(state);
        done({.nextRoute = route, .success = true});
    }

private:
    Evaluator m_eval;
};
```

#### 7. `ParallelNode` — 并行执行节点

```cpp
// src/service/agent/workflow/nodes/parallel_node.h

class ParallelNode : public IWorkflowNode {
public:
    // 多个子任务并行执行，全部完成后合并结果
    ParallelNode(const QString& id,
                 QList<std::shared_ptr<IWorkflowNode>> branches,
                 MergeStrategy merge = MergeStrategy::WaitAll);

    QString type() const override { return "parallel"; }
    void execute(WorkflowState& state, NodeCallback done) override;

    enum class MergeStrategy {
        WaitAll,        // 等全部完成
        WaitAny,        // 任一完成即可
        WaitMajority    // 多数完成

};
```

### 四、Checkpoint 与容错机制

```cpp

```

**容错策略**在 `WorkflowExecutor::executeNode` 中实现：

```cpp
void WorkflowExecutor::executeNode(const QString& nodeId) {
    auto* node = m_graph.node(nodeId);
    m_state.setCurrentNode(nodeId);
    emit nodeEntered(nodeId);

    // 超时保护
    if (node->timeoutMs() > 0) {
        m_timeoutTimer->start(node->timeoutMs());
    }

    // 保存断点
    saveCheckpoint();

    node->execute(m_state, [this, nodeId, node](NodeResult result) {
        m_timeoutTimer->stop();

        if (!result.success && m_retryCount[nodeId] < node->maxRetries()) {
            // 重试
            m_retryCount[nodeId]++;
            QTimer::singleShot(1000 * m_retryCount[nodeId], this,
                              [this, nodeId]{ executeNode(nodeId); });
            return;
        }

        emit nodeCompleted(nodeId, result);
        route(nodeId, result);
    });
}
```

### 五、如何用 DSL 定义工作流

#### 方式 A：C++ Builder API

```cpp
auto graph = WorkflowGraph()
    .addNode(std::make_shared<LLMNode>("plan", planConfig, agent, orch))
    .addNode(std::make_shared<ConditionNode>("check_tools", [](auto& s) {
        return s.get("need_tools").toBool() ? "use_tools" : "direct_answer";
    }))
    .addNode(std::make_shared<LLMNode>("tool_loop", toolConfig, agent, orch))
    .addNode(std::make_shared<LLMNode>("reflect", reflectConfig, agent, orch))
    .addNode(std::make_shared<ConditionNode>("quality_gate", [](auto& s) {
        return s.get("confidence").toDouble() > 0.7 ? "done" : "retry";
    }))
    .setEntryNode("plan")
    .addEdge("plan", "check_tools")
    .addEdge("check_tools", "tool_loop", "use_tools")
    .addEdge("check_tools", "reflect", "direct_answer")
    .addEdge("tool_loop", "reflect")
    .addEdge("reflect", "quality_gate")
    .addEdge("quality_gate", "__END__", "done")
    .addEdge("quality_gate", "plan", "retry")
    .setMaxIterations(3);
```

### 八、与现有代码的兼容策略

| 现有组件 | 改造方式 |
|---------|---------|
| `VideoAgent` | 改为 Workflow 的**入口封装**，内部创建 Graph + 调用 Executor |
| `PerceptionStrategy` | 包装为 `FunctionNode` |
| `ToolOrchestrator` | 包装为 `LLMNode`（带 Tool Calling） |
| `ReflectionEngine` | 包装为 `FunctionNode` |
| `VideoRAGRetriever` | 包装为 `FunctionNode` |
| `EventBus` | Executor 通过信号通知，UI 仍通过 EventBus 感知 |
| `DIContainer` | 新增 `WorkflowExecutor` + `WorkflowFactory` 注册 |

**关键原则**：现有 `ITool`、`AgentService`、`EventBus` 接口不变，引擎层是**增量新增**而非重构。

### 九、实现优先级

| 阶段 | 内容 | 预估工作量 |
|------|------|----------|
| **Phase 1** | `WorkflowState` + `IWorkflowNode` + `WorkflowGraph` + `WorkflowExecutor`（基础执行） | 3-4 天 |
| **Phase 2** | `ConditionNode` + `FunctionNode` + `LLMNode` + 路由逻辑 | 2-3 天 |
| **Phase 3** | 将现有 `VideoAgent` 改造为基于 Graph 的执行 | 2 天 |
| **Phase 4** | `Checkpoint` + Retry + Timeout | 1-2 天 |
| **Phase 5** | `ParallelNode` + `HumanNode` + `SubWorkflowNode` | 2-3 天 |
| **Phase 6** | JSON 配置解析 (`WorkflowFactory`) + 预设工作流 | 2 天 |

总计约 **12-16 天**即可完成一个功能完整的 Workflow 引擎。
