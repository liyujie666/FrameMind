# 视频 RAG 模型请求与失败回退修复

日期：2026-10-01。

## 问题与修复

旧构建将任务 system Prompt 拼入聊天用户消息，真正的 system 消息仍要求 Markdown 回答及工具检索。
新增 `AgentService::sendOneShot`：只发送任务 system 消息与证据 user 消息，不带聊天历史、视频背景或工具策略。
图片请求不携带本地 token 估算用的 width/height 扩展字段，超过图片上限明确失败；分段校正最多发送十张图。

请求通过 `LLMProviderService::getEndpoint` 使用用户配置的端点；活动提供商配置更新时同步刷新模型指纹。
构建默认 temperature 为 0.1，输出额度为 4096 token，可通过 `llm.build_max_tokens` 设置（1024–16384）。
首版不强制发送所有兼容提供商未必支持的 response_format，仍严格校验 JSON、事实类型和来源引用。

`ModelReply` 同时传递正文与错误；VideoAnalysisService 的构建结果继续携带上下文和产物状态。
HTTP 错误、空正文、输出截断、非正常结束、超时、JSON/schema/来源错误及图片读取失败均保留具体原因。
网络错误中匹配当前 API Key 的内容被替换为 `[redacted]`，不保存原始模型正文或请求证据。
55 秒通道超时直接终止请求并报告错误，不将截断正文当成功结果；协调器还有 60 秒排队/请求保护。
每个任务最多重试一次，重试提示包含校验失败原因与输出约束。

NetworkClient 在调用完成/错误回调之前释放旧 reply，避免后续清理误删回调刚启动的新请求。
SSE 支持 LF/CRLF 换行；`finish_reason=length` 明确标为输出截断，缺少正常结束信号也不会被视为完整结果。
取消构建会删除排队任务、终止正在运行的后台请求并丢弃其结果，随后可执行新构建。

## 失败后的展示与索引

- 单元只追加一次失败计数与具体原因，不逐页堆积相同占位文本。
- 全部证据页失败时跳过模型摘要，显示失败页数及去重后的原因；原始证据仍可检索。
- 零成功页的单元不生成 UnitSummary 向量或文本索引，失败说明不作为视频内容召回。
- 摘要只处理至少有一页成功的单元；短输入直接回退一次，长输入才选取八处互不重叠的摘录。
- 构建数据状态仍为 Partial，UI 在全部页失败时显示“理解失败（原始证据可用）”。

`pipeline=semantic_context_v4`、`build_request=isolated_json_v1` 纳入构建指纹；分类版本更新为 profile_v2。
旧派生结果不会被当作当前版本的兼容构建直接复用，兼容的转写、镜头及帧仍可复用。
升级后重新编译、启动应用，打开视频或点击“按此策略构建”执行新构建；旧数据库无需删除。

## 离线验证

新增 `video_model_channel_tests`，使用临时 SQLite、隔离的测试凭证和本地 HTTP/SSE 服务，执行真实
AgentService → OneShotVlmChannel → NetworkClient 路径。覆盖消息角色、图片、输出额度、端点覆盖及模型指纹刷新、
连续请求（含无 DONE 的正常结束）、HTTP 401 与脱敏、输出截断、缺少结束信号、内容过滤、超时及取消后继续。

VideoRAGTests 增加非 JSON、缺失 schema、虚构来源和 HTTP 错误的整条流水线用例，以及修复重试、
全部页失败跳过摘要、失败占位不入索引、短摘要回退不重复的回归检查。
主程序 Debug 构建及四套 CTest 已通过；构建开关矩阵结果见实现验收记录。

没有调用用户的在线模型或重新处理截图中的真实素材。这些检查确认请求协议和失败处理，
真实视频的模型输出质量仍需在新版本应用中重新构建验证。
