核心亮点逐一讲解
亮点 1：四层时序索引架构
"视频不同于文档，它有时间维度。我设计了一个四层索引结构：视频层存整体摘要，场景层按镜头切分并生成描述，事件层提取关键动作和台词，帧层保留关键帧和时间戳。

这样用户问粗粒度问题（'这个视频讲什么'）可以直接返回摘要，问细节问题（'00:32 画面里有什么'）可以精确定位到帧。这个设计让检索召回率提升了 40%。"

面试官可能追问：怎么切分场景？

"用 FFmpeg 的场景检测算法，基于帧间像素差异自动切分。每个场景提取 3-4 张代表帧，送给 VLM 生成视觉描述。"

亮点 2：多模态联合分析
"视频理解不能只看单帧，我做了两个优化：

第一，把 ASR 语音转写、OCR 可见文字、VLM 视觉描述三路信息融合，形成完整的场景理解。

第二，针对每个场景，我不是只给 VLM 看一张图，而是把场景内多张代表帧（开始、中间、结束）拼成时序网格，让 VLM 一次性看到状态变化。这样能捕捉到动作过程，相比单帧分析，关键信息遗漏率降低了 35%。"

面试官可能追问：为什么不直接用视频输入？

"成本和效率考虑。视频输入的 API 很贵，而且推理慢。多帧网格方案只需要一次 VLM 调用，成本可控，效果也够用。"

亮点 3：混合检索与重排
"这是整个系统的核心。我实现了一个 QueryPlanner，它会先分析用户问题的意图——是视觉类、语音类还是时序类问题，然后决定召回策略。

召回分四路：Dense Retrieval（BGE 文本向量 + CLIP 视觉向量）、BM25（处理专有名词）、Temporal（时间过滤）、Entity（实体指代消解）。

多路结果用 RRF 算法融合，再加上我设计的时序互证机制——如果同一时间窗口内有多个模态的证据互相支撑，就提升这条证据的可信度。最后用 Cross-Encoder 精排到 Top-5，准确率达到 82%。"

面试官可能追问：为什么用 RRF 而不是加权平均？

"RRF 对排序位置不敏感，不同召回源的分数尺度不一样，RRF 能自动归一化。而且它不需要训练，实现简单。"

亮点 4：证据驱动生成
"视频问答最怕的就是大模型瞎编，我做了两层溯源机制：

第一层，检索命中的证据不只是文本，还包括原始关键帧、时间戳、证据类型（视觉/音频/融合）。这些打包成结构化证据包回注给 VLM。

第二层，生成答案时强制 LLM 引用证据编号，UI 上展示每条证据的时间戳和缩略图，用户可以点击跳转验证。这样建立了答案到原始片段的完整映射链路，有效降低了幻觉。"

面试官可能追问：怎么保证 LLM 一定引用证据？

"Prompt 工程 + 后处理。Prompt 里明确要求引用证据编号，然后解析回答，提取出引用的证据 ID，和原始证据包做映射验证。"

亮点 5：Video Agent 工具编排
"我基于 Tool Calling 构建了一个 Video Agent，它有六个工具：视频搜索、场景分析、实体追踪、播放控制、时间跳转、反思引擎。

用户问复杂问题时，Agent 会自动规划工具调用序列。比如问'那个穿红衣服的人后来去哪了'，它会先调搜索工具找红衣人第一次出现的位置，再调实体追踪找后续出现，最后综合回答。

这个设计的好处是解耦：每个工具独立实现，可以灵活组合，支持多轮交互。"

面试官可能追问：工具调用失败怎么办？

"有重试机制和降级策略。如果工具调用失败，会触发反思引擎，分析失败原因（参数错误 or 无结果），然后调整参数重试，最多三次。实在不行就降级到纯检索模式。"

##Video Agent 工具编排  这部分你可以给我讲讲你的agent是如何工作的吗

"我的 Agent 采用了 ReAct 模式，也就是 Reasoning（推理）加 Acting（行动）。核心是一个多轮工具调用循环。

架构分三层：

VideoAgent 负责接收用户问题，先做 RAG 检索获取证据
ToolOrchestrator 负责管理多轮循环，协调 LLM 和工具之间的交互
ToolRegistry 管理 6 个具体工具的注册和调用
工作流程是这样的：

用户提问后，我先用 RAG 检索相关证据，把证据 + 问题 + 工具定义一起发给 LLM
LLM 可以选择直接回答（如果证据够），或者调用工具获取更多信息
如果 LLM 返回 tool_calls，Orchestrator 会解析工具名和参数，执行对应工具
工具执行完毕后，把结果回填到对话历史，再次发给 LLM
LLM 看到工具结果后，可以继续调用其他工具，或者生成最终答案
最多 5 轮或 10 次工具调用后强制结束，防止死循环
我实现了 6 个工具：

search_video_content：在视频中搜索符合描述的画面（调用 RAG）
get_transcript：获取指定时间的语音转文字
get_scene_info：获取场景的详细信息
control_player：控制播放器播放/暂停/跳转
seek_and_analyze：跳转并实时截图分析（索引不足时补充）
analyze_time_range：分析指定时间段（多帧采样）
关键设计点：

所有工具都是异步的，不阻塞 UI
工具完全解耦，通过接口注册，易于扩展
记录完整的工具调用轨迹，支持溯源和调试
对播放器操作强制工具调用，保证副作用一定执行
举个例子，用户问'穿红衣服的人后来去哪了'，Agent 会先调用 search_video_content 找到所有出现的位置，然后调用 get_scene_info 查看最后一次出现的场景细节，最后综合回答。整个过程用户能看到每个工具的调用过程和返回结果，完全透明可溯源。"
