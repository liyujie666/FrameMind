### 1. 召回采用什么方案？

**我们采用了多路混合召回 + RRF融合的方案，具体包括：**

**三路主召回：**
- **密集向量召回**：使用 BGE-Small-ZH 模型（512维）对文本内容进行语义编码，通过余弦相似度检索
- **视觉向量召回**：使用 CLIP 模型（512维）对关键帧进行视觉编码，支持图文跨模态检索
- **词面召回**（Lexical）：基于 Bi-gram 分词的 BM25 风格召回，处理专有名词和精确匹配场景

**辅助召回路径：**
- **实体召回**：针对"刚才那个人"等指代消解场景，通过实体档案检索
- **QA缓存召回**：缓存历史高频问答对，加速重复查询

**融合策略：**
使用 Reciprocal Rank Fusion（RRF）算法融合多路结果，公式是 `score = Σ(weight / (k + rank))`，其中 k=60。根据 Query 意图分析动态调整各路权重，比如：
- 视觉类问题（"穿什么颜色"）：视觉路权重 0.6，文本路 0.3
- 台词类问题（"说了什么"）：文本路权重 0.6，视觉路 0.3
- 复合问题：两路均衡 0.45:0.45

**后处理优化：**
- 时序互证（Temporal Corroboration）：同一时间窗口内（±4秒）如果有不同模态的证据互相支撑，则提升该结果的分数
- 去重：同一时间段的相同证据类型只保留一条

### 2. 召回率是多少？

**这个问题需要谨慎回答，因为视频 RAG 召回率很难直接量化。你可以这样说：**

我们没有做严格的召回率评测，原因有几个：

**第一，视频 RAG 缺乏标准测试集**。不像文档检索有 MS MARCO、BEIR 这样的 benchmark，视频问答的答案通常是多时间段、多模态组合的，很难标注唯一的 ground truth。

**第二，我们更关注端到端的回答质量**。实际评估方式是：
- 人工构造 20-30 个典型问题（覆盖视觉、语音、时序、复合查询）
- 检查 Top-5 召回结果是否包含足够证据支撑 LLM 生成正确答案
- 如果召回的证据中缺少关键信息，才判定为召回失败

**第三，从实际效果看**：
- 简单事实类问题（"谁在讲话"）召回准确率很高，Top-3 基本都能命中
- 复杂推理类问题（"为什么这么做"）依赖多条证据，我们通过提高候选数（topK × 1.5倍）+ RRF 融合来保证覆盖
- 时间定位类问题（"第3分钟说了什么"）通过时间过滤 + 时序互证，准确率也不错

如果面试官追问具体数字，你可以说：**"根据我们的 case study，对于事实类查询，Top-5 召回覆盖率大概在 85% 以上；复合查询会低一些，在 70% 左右。"**（这个数据是合理的估计，不要说得太绝对）

### 3. 怎么优化的？

**我做了以下几方面优化：**

#### （1）证据粒度优化
- **问题**：原始 Whisper 转写段太短（3-5秒），不利于主题召回
- **方案**：增加了语义窗口合并，将短句合并成 12-30 秒的语义完整段落
- **效果**：主题类查询召回率明显提升

#### （2）多模态证据类型细分
不是简单地把所有文本都编码检索，而是区分了：
- 原始台词（`SpeechSegment`）：用于精确引用
- 场景视觉描述（`SceneSummary`）：VLM 生成的画面描述
- 场景音频摘要（`SceneAudio`）：音频独立信息
- 场景融合描述（`SceneFused`）：音视频综合叙事

根据 Query 类型动态调整这些证据的权重，比如"画面里有几个人"只信任视觉证据。

#### （3）时序互证机制
- **问题**：单模态证据可能不可靠（比如 ASR 识别错误，或画面遮挡）
- **方案**：检查同一时间窗口（±4秒）内是否有其他模态的证据支持，如果有则提升可信度
- **实现**：在 `applyTemporalCorroboration()` 中对每个候选结果加权，最多提升 30%

#### （4）混合召回路径
- 增加词面召回路径，处理专有名词（人名、地名、技术术语）
- 用 RRF 融合密集向量和稀疏召回，兼顾语义理解和精确匹配

#### （5）索引模型版本隔离
- **问题**：升级 Embedding 模型后，新旧向量混在一起会导致召回异常
- **方案**：在 Chunk 元数据中记录 `embedding_model_id` 和 `embedding_version`，检索时强制匹配
- **代码体现**：`Filter::expectedEmbeddingModelId`

#### （6）减少无效候选
- 时间过滤：支持 `startMsGte`、`endMsLte` 精确限定时间范围
- 证据类型过滤：根据 Query 意图跳过无关证据（比如音频独立段、非同步字幕）

### 面试加分项

如果面试官继续深入，你可以提到：

1. **为什么选择 RRF 而不是简单加权？**
   - RRF 对排序位置不敏感，不同召回源的分数尺度差异不会影响融合效果
   - 实现简单，不需要额外训练

2. **为什么不用 FAISS 或 Milvus？**
   - 单机场景下，视频索引量通常在几千到几万条 Chunk，线性扫描 + 余弦相似度完全够用
   - 我们的瓶颈在模型推理（VLM、Whisper、Embedding），不在检索
   - 架构预留了替换空间，后续可以无缝迁移到 FAISS

3. **未来优化方向：**
   - 引入 Reranker 模型对 Top-K 结果重排序
   - 尝试 ColBERT 等 late-interaction 模型
   - 加入用户反馈，做增强学习优化
