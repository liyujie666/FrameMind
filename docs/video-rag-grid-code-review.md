日期：2026-10-02

## 完成的代码

- `UnitFrameEvidence` 绑定原始 sourceId、文件路径、PTS、稳定顺序及规划尺寸，补齐原始证据与传输图片之间的显式关系。
- 新增 `EvidenceGridComposer`：后台读取图片头，确定全部页面及拆页；逐帧读入并绘制固定网格，保持比例和完整画面，标签单独置顶，灰色交叉格表示空位。
- 1 帧为 1×1、2 帧为 2×1、3～4 帧为 2×2、5～6 帧为两列三行；超过布局容量或格内短边不足时顺序拆为连续子页。每条原始文本／帧证据分配一次，文字保持原有时间和 text_offset。
- 图片在后台编码为 JPEG，默认最大边长 2048、质量 85；请求沿协调器、工作池、单通道、AgentService 传递已编码字节和尺寸，有图页一张、纯文本页零张。requirePrepared 检查阻止静默退回旧的 1024 编码。
- 同页重试复用原 JPEG、映射和 carry，不重复读取或合成；仅活跃页持有图像，页终态或构建停止后释放缓存。
- 理解合同升级为 unit_grid_carry_v2，单独记录 carry/grid 版本和网格参数，并写入计划 JSON/fingerprint。并发额度保持运行配置，不改变原始证据兼容条件。
- 复用原始快照时补齐 textVectorAvailable 比较及全部原始帧 chunk 文件存在检查；不完整时进入现有重新提取路径。旧 JSON 保留 legacy 版本标识，不能命中新派生结果。
- 增加逐页／单元／阶段诊断及紧凑 artifacts 汇总；记录规划、读图、合成、编码、排队、请求、首字节／首内容、JPEG 尺寸字节、拆页、重试、carry 降级和 usage 可用性。
- 诊断 JSONL 位于 AppDataLocation/diagnostics/video-rag/build_id，每个文件最多 16MiB，不保存图片、Prompt 或 carry 正文，不自动删除原始资源。写入失败只影响诊断可用性，不改变发布状态。
- 新源文件加入 RAG target；应用 target 使用现有源码 glob。其他单通道／聊天调用维持默认图片编码选项。

## 静态审查结论

| 检查对象 | 核查及处理 |
|---|---|
| 来源与覆盖 | frames 及 framePaths/framePtsMs 校验一一对应；事实仍按本页原始 sourceIds 校验，operation 仍使用原始帧数；网格自身不生成事实来源 |
| 时间与顺序 | PTS 升序，同 PTS 按稳定原始顺序；重编号在全单元规划完成后发生，carry 编号基于最终页序；拆页后总页数固定 |
| 图像完整性 | 读取失败、尺寸变化、过大源图、编码失败均带具体原因，不使用空白格代替缺失原帧；空位仅来自布局未使用的格子 |
| 编码链路 | ImageEncodingOptions 贯穿两种生产通道入口，准备字节直接 base64；默认调用仍为 1024/JPEG80，尺寸元数据在正式请求发送前移除 |
| 并发与取消 | 后台仅处理不可变页/config/取消标记，回主线程后校验身份；规划未完成不会发请求；停止构建清理 watchdog、worker 及当前页缓存 |
| 重试 | 原 JPEG 和映射留在单元任务中，仅重试当前页；终态后才释放并推进，重复／迟到回调保护沿用 |
| 兼容与发布 | 合同及参数变更导致派生指纹变化，原始提取兼容独立判断；manifest JSON 保留 artifacts；未新增数据库 schema 或 BLOB |
| 恢复 | 计划新字段缺失解码为 legacy，活动构建原 JSON/artifacts 可恢复；没有新增断点续建能力 |
| 内存与字体 | 一次只解码一张原图，活跃页数受工作额度限制；64MP 原图解码预算；网格标签用固定程序字形，不需要后台访问 GUI 字体库 |
| 诊断副作用 | JSONL 正确换行，文件容量有界；错误及异常阶段仍保存紧凑状态；诊断文件失败不会导致业务 Partial |

审查中补齐了：专用编码在旧单通道入口的透传、预编码数量／尺寸检查、取消时图像缓存释放、错误编码结果的实际尺寸／字节记录、非法字节限制不能变成无限制，以及原始帧 chunk 的复用检查。
