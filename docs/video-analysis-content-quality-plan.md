## 1. 交付目标与范围

完成后应同时具备以下结果：

1. 时间线直接展示有内容逻辑的 VideoChapter，正文不再是带 pageId 的页摘要拼接。
2. 概览是全片综合，保留现有概览卡片和复制入口；正文没有分段时间、内部 ID、覆盖统计或错误信息。
3. 总结下方由类型化内容整理与探索区域组成，不再恢复旧语义单元／场景正文列表。
4. 有来源的关键条目可以回看，探索问题通过现有视频聊天链路提交，切视频或重建后不会串内容。
5. 全部展示产物随同一活动 buildId 保存，重启后无需调用模型即可恢复；旧构建可读，取消、失败和竞争发布不破坏旧活动版本。
6. 现有页并发、carry、证据网格、来源校验和模型请求保护保持有效，并通过真实视频验证质量与调用成本。

本版覆盖设计中全部主类型及 demo 展示模式。首轮真实样本优先软件运行展示、真实教程、课程和访谈，但这不缩减其他类型的策略合同与验收范围。

沿用现有播放器 SDK、ChatViewModel／VideoAgent／RAG、页工作池、网络通道和 JSON 存储。展示结果首版在候选构建完成后整体发布；不新增外部任务写入、不重复向量化探索问题或类型化笔记、不实现“只重建展示”的 RebuildScope、不新增并行综合工作池。

## 2. 当前基线与实施约束

规划时静态核对了设计、协调器、模型定义、CMake 和交互入口。当前仍缺少 presentation 模型与新生成阶段；页理解已有独立任务、UnitPageAnalysisResult、并发额度 1～3、1000 字符 carry、证据网格及一次完成屏障。

当前工作区至少有设计文档和 `src/util/video_rag_log.cpp` 的未提交修改。实际开发开始时重新记录 git status／diff，保护届时所有已有修改；不能按本文快照重置源码。

当前存在构建目录 `build/Desktop_Qt_6_9_1_MSVC2022_64bit-Debug`，CMakeCache 显示 Debug、BUILD_TESTING=ON、ONNX=ON、Whisper=ON。这仅证明配置存在；本次制定计划未构建或运行测试，不能认定当前基线通过。历史 P0～P3 验收早于后续网格等修改，不能替代新基线。

实施约束：

- 第一版保留页工作池调度；各单元页任务结束即释放 worker，全部叶子任务终态后通过现有屏障，再按 unitOrdinal 顺序执行单元综合。
- 新生成阶段使用协调器 `request()` 的构建生命周期；页阶段继续使用 `requestUnit()`，不走用户聊天生成构建内容。
- 运行任务身份与展示活动构建身份分开。缓存恢复、候选计算和新发布均有明确身份；同路径不等于同任务。
- 编解码、来源校验和候选存储随数据阶段逐步实现；P7 负责完整集成验收，不把持久化全部推迟到最后。
- mock 验证流程与合同，真实视频验证语义准确性；有效引用不能替代内容质量验收。
